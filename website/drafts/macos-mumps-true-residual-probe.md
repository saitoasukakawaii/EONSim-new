# 从真实残差定位本机 MUMPS 并行路径问题

## 目标与背景

面向需要迁移数值计算环境的开发者。学习目标是区分“求解器报告收敛”与
“返回的解满足当前方程”，并用最小复现缩小调查范围。

从Linux研究快照迁移到本机macOS arm64/PETSc3.25.6后，EONSim编译成功，
但并行MUMPS相关检查失败。它不同于仓库日常PETSc3.23.7锁，历史通过结果
不能自动证明这个新环境可用。

## 诊断步骤与证据分类

**理论：** 若已知向量为 `x*=1`，构造 `b=A*x*` 后，可以直接检查解误差
`||x-x*||inf` 和真实残差 `||Ax-b||2`。这一检查不依赖迭代器内部估计残差。
本例是三个未知量的非对称、严格对角占优线性系统，不代表FSI本身。

**实现：** 在源码基线 `92fef88ec6c7dad48cfe8a25ecdb79db48f9a8cc`，
`tests/verify_lu_reuse.cpp` 检查实际LU计数与非线性解。新增的证据探针
只调用PETSc矩阵/向量/KSP接口，不链接EONSim，排除了应用装配与耦合算法。

**验证：** 本机默认MUMPS单进程探针通过；2/4进程的解误差均为1，真实残差
约6.0564。显式设置 `-mat_mumps_icntl_20 0` 后，三个进程配置的解误差均
约2.22e-16，真实残差约8.88e-16。相关EONSim Debug/Release检查随后各4/4通过。
原物理模型和容差保持不变。

完整源码、实际命令、环境和原始日志见
[本机重算证据](../../docs/research/data/macos-recompute-2026-11-09/README.md)。
使用时应先阅读该报告；不能仅复制一个选项就宣称消除了所有环境差异。

## 修改与限制

没有修改系统PETSc安装或EONSim求解器。新增独立复现和环境记录，显式集中
右端仅用于本机并行检查。当前长程重算使用已验证的单进程默认路径。

上游具体缺陷尚未定位，不能据此声称所有PETSc3.25.6或所有macOS安装都有
相同问题。没有性能测量或多节点扩展结论；集中右端的内存与扩展限制不能
从三未知量实验推断。最终FSI生产资格仍须独立完成周期、解析和误差预算。

## 进一步检查

在另一份受控依赖构建中复现同一探针，再比较分布式右端传递的实际数组。
改变依赖版本、编译配置或后端时，保存失败记录与完整命令，不把线性迭代
的终止标志作为真实残差验证的替代品。本篇保留为草稿，尚未发布。

## 后续串行采用：完整历史与独立质量积分

基于 `f1defb3` 的[新细网格启动证据](../../docs/research/data/macos-fine-startup-2026-11-09/README.md)
覆盖直接前后对照、两个缓存窗口及实际重启。112对完整HDF状态的560个数据集全部比较，
时钟和元数据精确一致；独立重建四面体体积与P1质量积分复现最大节点差7.46e-17、
相对质量差5.61e-15。脚本第一次因括号语法错误未执行检查，修正后返回0。

本机窗口32耗时约74.89秒，相对两次直接解470.00/471.33秒明显减少，
但这仍是32步启动段、单rank、共享机器的局部证据，不外推为并行扩展性或长期物理正确性。
采用后六周期计算从零启动；周期场、解析误差和独立误差预算仍各自验收。

## 参考后端也需要新环境证据

2026-11-09，基于39b4011，固定svFSI源码新增隔离Trilinos13.2构建，不改原可执行程序。
[本机七组对照](../../docs/research/data/macos-reference-backend-2026-11-09/README.md)中，新构建
显式FSILS与旧程序完全一致；ILUT加载段与真实重启满足既定字段和完整历史误差限。
从零启动的保存方程范数有8.0661e-28差异，因此这次额外逐位相等检查仍记为失败。
不能删掉失败检查来声称原筛查通过。后续独立细网格试验预先引用仓库既有2e-9
保存norm界限，同时另报逐位是否相等；停止条件和物理验收门槛不变。

收集器还必须按真实整数步识别带前导零文件名，并排除stFile_last这类非数字别名。
两次解析失败均只重做分析，保存原日志和数值文件，不启动重复计算。

后续实际细N800筛查和独立复核已完成210对状态，最大完整history差5.86888e-19，
保存norm差2.09443e-28，实际10步replay完全一致；[采用证据](../../docs/research/data/macos-reference-backend-2026-11-09/fine-screen/README.md)
记录了原误差限、二进制和输入哈希。ILUT启动段154.94秒较原FSILS83.05秒更慢，
所以这里只证明可用于进一步计算的数值一致性，不能宣传加速。新完整细研究从零开始，
尚待全程收敛、场和独立误差预算。


### 无须线性求解的接受态与实际MPI加载证明

新粗N800双rank从零完成24周期后，32步充分加载窗口和16步同分区重放
通过全局五场与352个native datasets检查，保存时钟完全一致；[完整证据](../../docs/research/data/macos-elastic-mpi-loaded-2026-11-09/README.md)。
这仍依赖显式本机MUMPS集中右端，不是默认后端或完整物理资格。

原控制器一律要求KSP原因正值，因第一步无须线性求解而误报。原输入
绝对门槛1e-13下，首步残差5.54e-14已被SNES接受且线性调用计数为零；
此时KSP0表示未执行线性求解。应结合接受态和真实调用判断，不能把
未执行与失败混为一谈，也不能对已执行但未收敛的线性求解沿用该例外。
原失败保留，只接续剩余窗口，不重复已完成的物理时间步。
