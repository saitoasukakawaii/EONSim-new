## 持续开发协议

1. 开始读取本文件、[任务队列](CODEX_TASK_QUEUE.md)、最近的 [会话日志](CODEX_SESSION_LOG.md) 与 AGENTS.md；检查 `git status`、HEAD、远端 main 和相关代码。历史通过记录只对记录的提交有效。
2. 从队列选一个依赖满足、可独立验收的 ready 任务；写入状态 active、分支、基线提交。阻塞任务记录原因，改选不依赖阻塞项的任务。候选算法需先完成其规格，不能猜测物理约定。
3. 从最新 main 创建 `feat/<任务>`、`fix/<任务>` 或 `docs/<任务>` 独立分支。已有隔离 checkout 可复用；不默认新建 worktree。保护已有用户改动，不在 main 上提交。
4. 沿现有实现完成任务，按 [最小验证](BUILD_AND_VALIDATION.md) 运行对应检查。文档任务运行文档/网站检查，不为此重跑全部数值测试。
5. 更新本文件的状态摘要、队列状态和会话日志。日志记录基线/分支、实际文件、完整命令及工作目录、退出码、通过/失败/跳过/未运行、证据位置、剩余问题和下一步。
6. 对有实质技术内容的任务作知识沉淀判断，记录“有/无及理由”；有则按 [贡献规范](../../website/development/contribution.md) 生成 website/drafts/ 草稿。没有新知识不凑文章。
7. 提交独立分支，推送并创建目标为 main 的 PR，记录 PR URL，状态改为 review。等待人工审核；不得自行合并或发布草稿。创建 PR 失败则记录具体阻塞、远端分支和恢复操作，不宣称已创建。
8. 新任务恢复时核对 PR 实际状态：已合并才将任务标为 done；被关闭未合并需重新评估。继续 active 任务前确认分支及未完成步骤；日志冲突保留两份事实并按任务 ID 整理。
