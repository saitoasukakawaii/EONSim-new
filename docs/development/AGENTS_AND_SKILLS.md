# 项目文档、AGENTS.md 与 skill 的使用方法

## 建议：项目文档为主，AGENTS.md 作为入口，skill 可选

| 载体 | 保存什么 | 如何生效 |
|---|---|---|
| 根目录总原则＋docs/architecture | 项目的架构决定、数值语义、设计原因 | 人阅读；agent 经 AGENTS.md 的任务路由按需读取 |
| 根目录 AGENTS.md | 高频且短的规则、项目状态、文档入口 | Codex 按指令文件发现规则读取 |
| 模块目录 AGENTS.md | 该模块独有的少量增量约束 | 注意工作目录与发现范围；根入口已要求处理子目录时读取 |
| 项目 skill | 本项目某项反复执行的操作方法 | 显式调用或描述匹配时加载 |
| 个人 skill | 跨项目稳定的通用方法 | 在支持的位置安装并确认发现后使用 |

普通 Markdown 不会仅因被复制到仓库就全部自动成为 agent 指令。skill 也不适合替代项目架构事实，否则长期容易与代码和仓库文档分叉。

## 如何放入实际项目

本工作区已经是 EONSim-new 的实际开发仓库。以下仅供向另一个工程迁移规则时参考：

1. 把总原则文件和相关 docs 子目录一起移入目标仓库，保持相对链接；不要只复制总入口。
2. 合并目标根 AGENTS.md 的相关规则和路由，保留其中已有有效要求，不整文件覆盖。
3. 先根据已有代码修改 L1 的技术栈/目录和开发路线。“自有 C++17＋PETSc＋Tet4”是本方案默认，不应迫使已有 Fortran 或成熟框架项目重写。
4. 原仓库已明确的离散、字段、构建命令写回对应主题文档，使当前有效方案只有一份。
5. 本地研究记录中的源码定位已改为工程相对路径和原提交；它们是历史审查来源，不是当前工程运行依赖。九个上游的网络引用已固定 SHA。

迁移的是约束和已有证据。没有必要把所有研究项目作为 submodule、下载完整依赖，或为文档另建生成系统。

## 文件名与发现规则

标准名称是 **AGENTS.md**（复数），不是 agent.md。Codex 默认先读全局指令，再沿项目根到当前工作目录的路径读取项目指令；每个目录优先 AGENTS.override.md，否则 AGENTS.md，再考虑已配置的回退文件名。靠近工作位置的指令更具体；它不会因为根目录中有许多子目录，就自动递归加载所有子目录文件。[官方指令说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

因此根 AGENTS.md 应写清任务路由，并要求编辑模块前读取该模块局部文件。不要仅把关键规则藏在一个尚未进入的子目录。默认指令合并有容量上限（官方当前说明为 32 KiB）；长架构文档通过路由读取，避免塞进常驻指令。不要为了“确保优先”额外创建 AGENTS.override.md，它可能遮盖原有入口。[同一官方说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

修改后保存，并在新的运行/会话中确认载入；可以要求 agent 复述当前采用的约束与文件来源，避免继续依赖旧会话中已缓存的指令。

## 怎么编辑 AGENTS.md

直接使用普通文本编辑器编辑 UTF-8 Markdown。保留四类内容即可：项目当前状态、任务到文档的路由、少数不可破坏的数学/并行规则、真实可执行的验证方法。当前工作区根文件就是可用版本，不需要额外写一个同义 agent.md。

代码出现后，把构建说明中的示意命令换成实际命令；未实现前保留“规划”说明。规则应可操作，例如“残量评价不修改已接受材料历史”，而不是泛泛的“遵循最佳实践”。

仅在模块确有独有约束时增加局部文件。以下是将来 src/physics/AGENTS.md 的**示例**，当前 src/physics 已存在，但没有该局部 AGENTS.md：

```markdown
# 物理核局部约定

遵循根 AGENTS.md，并按本次修改读取离散算子/耦合状态文档。

- 局部计算输入包含几何、候选状态、只读已接受历史和材料参数。
- 不在积分点循环内通信、打印、配置查找或提交历史。
- 增加材料依赖时同时处理对应切线；用近似导数则明确算法。
- 修改公式时只做一个适当的方向导数或解析算例检查。
```

局部文件写增量，不复制根文件全文；无需给每个目录创建 AGENTS.md。文档分层是项目组织方式，不改变工具/系统实际的指令优先级。

## 什么时候凝练 skill

出现重复流程时再提炼，例如“新增一个物理场并完成其最小算例”或“定位 MPI 装配错误”。本次提供一个 [hpc-feature 模板](../skill-templates/hpc-feature/SKILL.md)，仅保存开发方法；项目的字段顺序、依赖版本、材料公式仍在仓库文档中维护。

该模板放在 docs/skill-templates 下，**尚未安装，不会自动发现**。需要使用时，将整个 hpc-feature 目录放到目标项目的 .agents/skills/hpc-feature/，保持 SKILL.md 文件名及 YAML 的 name/description。Codex 当前官方文档说明会发现仓库路径上的 .agents/skills，另支持个人 ~/.agents/skills；安装后先确认技能出现在可用列表，再显式请求“使用 $hpc-feature 实现……”。不同宿主还可能提供额外技能目录，以实际发现结果为准。[官方 skill 文档](https://learn.chatgpt.com/docs/build-skills)

不建议立即把本项目全部设计安装成个人全局 skill：它会把 PETSc、Tet4、字段顺序等项目假设带入其他工程。个人 skill 只保留“先确认现有架构、做一个纵向闭环、选择相关验证”的方法。

当前已提供仓库级 [eonsim-knowledge-capture](../../.agents/skills/eonsim-knowledge-capture/SKILL.md)，按根 AGENTS.md 对有复用价值的实质技术成果使用；hpc-feature 仍只是未安装模板。无新技术成果的文档维护不制造文章。
